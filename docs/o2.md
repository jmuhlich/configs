# nf-core/configs: Harvard Medical School O2 Cluster configuration

This is the nf-core config for the[Harvard Medical School O2
Cluster](https://harvardmed.atlassian.net/wiki/spaces/O2).

## First-time Nextflow setup

You must install Nextflow yourself. From an interactive job, run the following
commands:

``` shell
module load java
curl -s https://get.nextflow.io | bash
```

## Running nf-core pipelines

Only pipelines with `conda` support for all tools are likely to work without
further setup, but a selection of other pipelines requiring Apptainer containers
have also been verified. Some pipelines also have a custom configuration tuned
specifically for O2. The following is a list of validated pipelines and any
notes for use:

* nf-core/mcmicro: No further configuration needed

## Recommended Slurm job script

Fill in the PIPELINE name and VERSION and add all necessary pipeline parameters
on the last line. If you have access to the `gpu_quad` partition and the
pipeline you're running has GPU-accelerated modules, append `,gpu` to the
`-profile` parameter value, e.g. `-profile o2,gpu`. If your pipeline is not in
the validated list above, append `,conda` to the profile parameter value but be
aware that not all pipelines have complete conda support.

To run a pipeline's minimal test dataset and verify everything is working before
submitting your actual workload, append `,test` to the profile parameter. Check
the pipeline's documentation for further information about running its test
profile.

Adjust SBATCH time, partition, and job-name if desired. The given SBATCH mem
limit should be OK for most pipelines.

Save the script as `submit.sh` and run `sbatch submit.sh` to launch. Monitor the
`slurm-*.out` log file to review progress and warning/error messages.


``` bash
#!/bin/bash
#SBATCH --time=5-0
#SBATCH --partition=medium
#SBATCH --job-name=nextflow
#SBATCH --mem=2g

module purge
module load java

export NXF_JVM_ARGS='-Xmx1g'

~/nextflow run nf-core/PIPELINE -r VERSION -profile o2
```
